# Agent-platform capability benchmark: Gaia, Claude Octopus, OpenClaw, and Hermes Agent

Date: 2026-08-30  
Status: research synthesis; advisory; no implementation or effect authority  
Question: should Gaia be at least as capable as the useful combined capabilities of Claude Octopus, OpenClaw, and Hermes Agent?  
Scope: orchestration/fanout, provider/model routing, planning/skills, memory/RAG, long-running jobs, self-improvement, tools/MCP, browser/computer use, scheduling/triggers, multi-repository GitHub automation, observability, fault recovery, security/sandboxing, costs/quotas, remote operation, and human approval

## Executive verdict

The literal claim should be **rejected**. Gaia should not become the union of three large agent products. That would erase its strongest property: a small, replayable, zero-authority coordination kernel whose execution, publication, spend, credentials, and source mutation remain outside the six-verb bus ([Gaia README](../../README.md#the-tool-surface--exactly-six-verbs)). The external systems solve different product problems:

- Claude Octopus is a Claude Code escalation layer for multi-provider research, councils, reviews, worktree fanout, and scheduled workflows. Its useful core is **heterogeneous review with visible contribution and cost gates**, not its command/persona count ([Octopus README at `6265807`](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/README.md), [v10 execution contract](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/V10-MIGRATION.md#execution-truth)).
- OpenClaw is a personal-agent gateway spanning chat channels, remote nodes, browser/computer surfaces, model/provider fallback, tools, sessions, memory, schedules, and operator UIs. Its useful core is **remote reach plus a mature capability-policy plane**, not making every surface part of Gaia ([OpenClaw README at `0790d9f`](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/README.md#highlights), [security model](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/gateway/security/index.md)).
- Hermes Agent is a broad autonomous-agent runtime with subagents, durable Kanban work, provider routing, memory/skill evolution, background work, schedules, messaging gateways, browser/computer use, and checkpoints. Its useful core is **durable work ownership, progress supervision, and separable auxiliary models**, not autonomous self-modification by default ([Hermes delegation](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/delegation.md), [Kanban](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/kanban.md)).

The defensible restatement is:

> Gaia should be able to **coordinate, constrain, observe, and evidence** the useful outcomes supplied by those systems, either through a small native primitive or a governed adapter, while explicitly refusing capabilities that would widen the kernel's authority or destroy replayability.

On that standard, Gaia is already ahead in several narrow but important areas: explicit zero-effect coordination, content-addressed evidence, fail-closed replay, typed `UNKNOWN`, bounded human grants, exact mutation intent, and separation between advisory state and effect adapters ([Gaia architecture](../../README.md#architecture), [crash recovery](../crash-recovery.md), [GitHub operator](../github-portfolio-operator.md), [candidate publication](../../README.md#candidate-publication)). It is behind on durable attempt supervision, provider/cost policy, MCP-client and tool registries, remote ingress, and recoverable scheduled work. Those are the minimal gaps. Browser automation, chat networks, model catalogs, and skill marketplaces should remain integrations.

Five consequences should govern the next slices:

1. **Collective intelligence means independent information, not agent count.** Blind first passes, disclosed model/provider/evidence dependencies, preserved dissent, and one authority-bearing synthesis matter more than a council quorum. Octopus v10 correctly refuses to count two Anthropic-family seats as independent verification; OpenClaw and Hermes isolate child transcripts by default, but context isolation alone does not establish error independence ([Octopus routing](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/V10-MIGRATION.md#routing-and-fable), [OpenClaw subagent context](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/tools/subagents.md#context-modes), [Hermes delegation context](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/delegation.md#how-subagent-context-works)).
2. **Durable shared state must remain smaller than executor state.** Gaia needs work, attempt, lease, dependency, evidence, budget, and terminal-result records; it does not need to absorb every provider transcript, browser profile, channel session, or skill store.
3. **SSE/HTTP/WebSocket/stdio are transports, never authority.** OpenClaw demonstrates useful SSE, streamable-HTTP, stdio MCP, and remote Gateway WebSocket paths, but also documents that live approvals/events can disappear with a disconnected bridge. Gaia should isolate each transport adapter, use bounded queues and resume cursors where supported, and derive no approval or completion from connection state alone ([OpenClaw MCP transports and limits](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/cli/mcp.md)).
4. **Scheduling is an external wake mechanism, not a privileged kernel loop.** The triggered run must still present a pinned contract, freshness, deduplication key, budget, authority class, and stop conditions.
5. **Zero additional cost is an admission constraint, not a pricing promise.** Gaia already has a subscription-backed tracer and zero-cost advisory proposals. Octopus can use existing Codex/Antigravity/Copilot subscriptions or local Ollama, but even those seats are subject to quota and policy; Hermes and OpenClaw cost surfaces are estimates rather than universal hard caps ([Gaia real tracer](../../README.md#real-subscription-backed-agent-tracer), [Octopus cost sources](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/README.md#providers-and-what-they-cost), [OpenClaw cost limits](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/reference/api-usage-costs.md), [Hermes provider caveats](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/integrations/providers.md)). The default Gaia admission mode should therefore allow only already-authorized subscription seats, local models, and zero-LLM jobs, with `maxAdditionalPaidCost: 0`; any API-billed path requires an explicit superseding budget grant.

## Method and evidence labels

Only first-party sources were used: official repositories, versioned source/docs, release pages, and OpenClaw's official site. No benchmark claim below is treated as established merely because a maintainer wrote it.

- **Verified**: documented behavior corroborated by a shipped source tree, reference documentation, tests, or an explicit implementation contract at the pinned revision.
- **First-party claim**: a maintainer or product statement not independently reproduced here.
- **Inference**: a Gaia-specific conclusion derived from verified facts.
- **Unknown**: the available primary evidence does not justify a conclusion.

## Verified capability profiles and marketing boundaries

### Claude Octopus v10.0.0

Verified useful capabilities include explicit multi-provider research/debate/council workflows, isolated worktree workers, provider-specific routing, cost preflight and hard council caps, scheduled workflows, a GitHub-aware reaction engine, and a v10 append-only provider-seat lifecycle in which zero exit status alone does not make output eligible for synthesis ([command reference](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/COMMAND-REFERENCE.md), [architecture](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/ARCHITECTURE.md), [v10 migration](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/V10-MIGRATION.md)). The scheduler wraps workflows with a single-run lock, timeouts, per-run/day budgets, kill switches, a security allowlist, and run metadata ([scheduler](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/SCHEDULER.md)).

Qualifications:

- The README's claim that a 75% consensus gate catches disagreements before production is not a correctness guarantee. The architecture defines that gate as a subtask-success percentage; correlated models can still agree or complete successfully while being wrong ([README claim](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/README.md), [gate definition](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/ARCHITECTURE.md#develop-phase-tangle)).
- Provider “strengths” and role mappings are maintainer policy choices, not a reproduced evaluation. V10's disclosure that Fable and Opus share a provider family and do not count as independent verification is the more defensible rule ([routing disclosure](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/V10-MIGRATION.md#routing-and-fable)).
- The privacy statement “collects nothing” means the plugin does not phone home. Configured provider workflows still transmit prompt content directly to those providers, under each account's retention policy ([privacy](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/PRIVACY.md)).
- The security document is partly stale at this tag: its supported-version table names 9.x rather than v10. ## Adoption ledger by normalized capability

Each item treats the attractive feature as a hypothesis rather than a requirement. “Adopt” means a small Gaia-native primitive; “emulate” means reproduce the outcome while preserving Gaia's contracts; “integrate” means keep the implementation outside the kernel behind a governed adapter; “refuse” means make the non-capability explicit.

### 1. Orchestration and fanout — **adopt a durable attempt contract; integrate executors**

- **External capability:** Octopus exposes heterogeneous councils and isolated worktree workers; OpenClaw exposes bounded nested session subagents; Hermes separates ephemeral delegation from durable Kanban work ([Octopus council](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/COMMAND-REFERENCE.md#octocouncil), [OpenClaw nesting](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/tools/subagents.md#nested-sub-agents), [Hermes Kanban](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/kanban.md)).
- **Adoption value:** durable ownership, attempt identity, dependency evidence, explicit completion and recovery would make Gaia's four-lane factory operable beyond one process.
- **Hidden cost:** every nesting level multiplies contexts, cost, correlation, cancellation edges, and mutable ownership. A generic agent tree would duplicate host runtimes and weaken the one-owner rule.
- **Strongest counterargument:** Gaia's existing four-lane ceiling plus explicit human decomposition may be sufficient; better agents may outperform larger fleets.
- **Simpler alternative:** add `work`, `attempt`, `lease`, `dependency`, and terminal-result records outside the six-verb bus, while delegating actual execution to Codex/Claude/Hermes/OpenClaw adapters.
- **Falsifier:** the primitive fails if a crash, duplicate completion, late child, or owner loss can make two attempts both authoritative or make a completed attempt disappear.
- **Rejection criterion:** reject nested native fanout if the smallest end-to-end tracer bullet cannot show independent information gain greater than coordination and token cost at the supported four-lane ceiling.

### 2. Provider and model routing — **adopt explicit resolution receipts; integrate provider runtimes**

- **External capability:** all peers pin or route models; OpenClaw and Hermes rotate credentials and fall back, while Octopus v10 records requested and resolved provider/model/effort and discounts same-family “independence” ([Octopus routing](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/V10-MIGRATION.md#routing-and-fable), [OpenClaw failover](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/concepts/model-failover.md), [Hermes fallback](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/fallback-providers.md)).
- **Adoption value:** exact provider/model/policy provenance, declared independence class, and visible fallback prevent silent semantic drift.
- **Hidden cost:** model catalogs, OAuth, provider errors, and pricing change continuously; a native router becomes a permanent compatibility product.
- **Strongest counterargument:** exact user-selected models with no automatic fallback are more reproducible and easier to govern.
- **Simpler alternative:** Gaia defines a provider-resolution request/receipt schema; a host adapter resolves it and returns actual identity, snapshot, auth class, cost class, and fallback reason.
- **Falsifier:** two byte-identical requests under the same pinned manifest resolve differently without a new receipt or declared external change.
- **Rejection criterion:** reject silent cross-provider fallback for authority-bearing evaluation or effects; fail closed unless the contract pre-authorizes the fallback set and re-evaluation policy.

### 3. Planning and skills — **emulate progressive disclosure; refuse a kernel skill marketplace**

- **External capability:** Octopus packages workflows/personas, OpenClaw loads bundled/managed/workspace skills, and Hermes supports plans, progressive skill loading, `/learn`, and goal loops ([Octopus commands](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/COMMAND-REFERENCE.md), [OpenClaw skills](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/tools/skills.md), [Hermes skills](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/skills.md)).
- **Adoption value:** explicit, versioned procedure packages reduce prompt repetition and can bind work to a plan or verification contract.
- **Hidden cost:** skills are executable policy and a supply-chain surface; overlapping triggers and automatic updates make behavior non-reproducible.
- **Strongest counterargument:** host agents already have mature skill systems. Duplicating them inside Gaia adds no unique control-plane value.
- **Simpler alternative:** Gaia records skill identifier, immutable digest, source, declared capabilities, and loaded references in an execution contract; the host remains the skill engine.
- **Falsifier:** replay cannot identify which exact skill text and assets influenced a decision.
- **Rejection criterion:** refuse installation or auto-learning through the kernel, and reject any skill that can grant itself tools, authority, spend, or persistence.

### 4. Memory and RAG — **adopt evidence-grade retrieval metadata; integrate memory backends**

- **External capability:** OpenClaw implements hybrid vector/keyword retrieval and background consolidation; Hermes implements bounded user memory plus FTS and optional semantic providers; Octopus delegates persistence to external memory tools ([OpenClaw memory](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/concepts/memory.md), [Hermes memory](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/memory.md), [Octopus memory integrations](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/README.md)).
- **Adoption value:** Gaia already has the right seed: retrieval results are content-addressed observations with `authority: NONE`, and stale-only evidence becomes `UNKNOWN` ([Gaia search](../../README.md#local-hybrid-semantic-search)). Extending source revision, validity, ranking method, and derivation would support auditable context.
- **Hidden cost:** personal memory adds deletion/privacy duties; automatic consolidation can amplify prompt injection, stale beliefs, and summary errors.
- **Strongest counterargument:** repository facts and immutable evidence are enough for Gaia's coordinator role; a user-personality memory system is outside scope.
- **Simpler alternative:** keep memory engines external; standardize read-only evidence results and contradiction/invalidation links.
- **Falsifier:** retrieved content can affect an authority field without an exact source revision and an intervening accepted decision.
- **Rejection criterion:** refuse model-written durable memory in the kernel; reject any backend that cannot enumerate provenance, retention, invalidation, and deletion behavior.

### 5. Long-running jobs — **adopt durable attempts with `UNKNOWN`; integrate process supervisors**

- **External capability:** OpenClaw persists task and cron state; Hermes distinguishes recoverable completion delivery from non-resumable child execution; Octopus supervises scheduled process groups with locks, timeouts, cost checks, and kill switches ([OpenClaw cron](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/automation/cron-jobs.md), [Hermes delegation durability](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/delegation.md#lifetime-and-durability), [Octopus scheduler](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/SCHEDULER.md)).
- **Adoption value:** restart-safe ownership, progress leases, bounded cancellation, and `UNKNOWN` after ambiguous failure are prerequisites for AFK factory work.
- **Hidden cost:** exactly-once local events do not produce exactly-once external effects; reconciliation and fencing are adapter-specific.
- **Strongest counterargument:** OS services and existing gateways already supervise processes better than Gaia should.
- **Simpler alternative:** adopt only durable intent/attempt/result/reconciliation records and one supervisor adapter interface.
- **Falsifier:** kill at every boundary between intent, external effect, observation, and receipt; any duplicate or unidentifiable effect falsifies the design.
- **Rejection criterion:** reject unattended effects when the target lacks an idempotency key, state precondition, or read-after-crash reconciliation path.

### 6. Self-improvement — **adopt advisory proposals; explicitly refuse autonomous kernel mutation**

- **External capability:** Hermes' background reviewer can propose/write memory and skills, OpenClaw can consolidate/promote memory, and Octopus can react or run retrospectives ([Hermes background review](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/agent/background_review.py), [OpenClaw dreaming](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/concepts/memory.md#dreaming), [Octopus reaction engine](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/README.md#built-in-reaction-engine)).
- **Adoption value:** systematic proposals from failures and repeated corrections can improve procedures faster than manual discovery.
- **Hidden cost:** the evaluator, memory, policy, and agent can form a self-confirming loop; poisoned evidence becomes durable behavior.
- **Strongest counterargument:** “self-improvement” is mostly policy and memory editing, not verified capability improvement, and should not outrank stable governance.
- **Simpler alternative:** emit a content-addressed change proposal with baseline, holdout, counterargument, expiry, rollback, and requested capability; require independent review and a separate effect grant.
- **Falsifier:** held-out outcomes do not improve, regression/incident rate rises, or the proposer can modify its own acceptance test.
- **Rejection criterion:** explicitly refuse automatic mutation of Gaia source, schemas, authority policy, provider policy, evaluators, or trusted skills.

### 7. Tools and MCP — **integrate through a capability manifest; keep six kernel verbs**

- **External capability:** OpenClaw has a mature MCP server/client registry with OAuth, TLS, tool filters, timeouts, failure pausing, and lifecycle cleanup; Hermes supports local/remote MCP servers; Octopus projects workflows as MCP tools ([OpenClaw MCP](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/cli/mcp.md), [Hermes MCP](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/mcp.md), [Octopus MCP](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/README.md#works-with-openclaw)).
- **Adoption value:** governed tool discovery would let Gaia coordinate existing ecosystems without reimplementing their capabilities.
- **Hidden cost:** MCP servers are executable dependencies with mutable schemas, credentials, network access, and prompt-injection output.
- **Strongest counterargument:** the host agent already owns MCP. Gaia needs receipts from tool use, not another registry.
- **Simpler alternative:** define an adapter manifest containing exact server/version, transport, tool allowlist, input/output schema digest, data-flow class, cost class, timeout, and authority class. The host opens the connection.
- **Falsifier:** a server can add or change a tool without invalidating the manifest, or tool output can become an instruction/authority.
- **Rejection criterion:** do not add a seventh bus verb; reject dynamic unpinned tools, implicit write tools, literal committed credentials, or a server whose effects cannot be receipted.

### 8. Browser and computer use — **integrate as high-risk effect adapters**

- **External capability:** OpenClaw supplies isolated/signed-in/remote Chromium paths and node proxying; Hermes supplies several browser engines and CUA over MCP; Octopus consumes browser capabilities but does not own the underlying UI-control guarantees ([OpenClaw browser](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/tools/browser.md), [Hermes browser](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/browser.md), [Hermes computer use](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/computer-use.md)).
- **Adoption value:** browser and UI actions unlock signed-in systems without APIs and provide visual verification.
- **Hidden cost:** DOM/page content is hostile input; signed-in profiles carry ambient authority; UI targets drift between observation and click.
- **Strongest counterargument:** purpose-built APIs/connectors are more deterministic, testable, and auditable.
- **Simpler alternative:** integrate OpenClaw/Hermes/Codex browser drivers only after a low-risk read-only tracer; bind origin, profile, tab, target, screenshot/snapshot digest, intended action, and precondition.
- **Falsifier:** the adapter acts on a different origin/account/element/state than the reviewed intent, or cannot prove what changed.
- **Rejection criterion:** refuse autonomous password entry, security-setting changes, payment, publication, merge, or destructive UI actions without exact just-in-time human approval and target remeasurement.

### 9. Scheduling and triggers — **integrate OS/gateway schedulers; adopt a trigger envelope**

- **External capability:** Octopus has a single-process scheduler with budgets and kill switches; OpenClaw persists cron, event watchers, command jobs, and delivery; Hermes supplies cron, heartbeats, and HMAC webhooks ([Octopus scheduler](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/SCHEDULER.md), [OpenClaw scheduled tasks](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/automation/cron-jobs.md), [Hermes webhooks](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/messaging/webhooks.md)).
- **Adoption value:** delayed and recurring work is essential for monitoring, queue draining, and remote operation.
- **Hidden cost:** schedules outlive the conversation, credentials, model policy, and original assumptions; trigger scripts become unattended code execution.
- **Strongest counterargument:** Task Scheduler/systemd/Codex heartbeats already provide durable clocks and lifecycle controls.
- **Simpler alternative:** Gaia accepts a signed `triggered-run` envelope from an external scheduler, verifies contract revision/expiry/budget/authority, and records the outcome.
- **Falsifier:** a disabled/expired/superseded contract can still fire or two schedulers can start the same run id.
- **Rejection criterion:** refuse an in-kernel cron engine and agent-authored headless trigger code; require read-only trigger evaluation and effects in a separately authorized payload.

### 10. Multi-repository GitHub automation — **adopt the existing portfolio path incrementally**

- **External capability:** Octopus reacts to issues/PR/CI; Hermes can use GitHub webhooks, `gh`, skills, worktrees and per-board repos; OpenClaw can drive GitHub through tools/webhooks but has no verified native cross-repo dependency plane. Gaia already has the strongest purpose-built organization survey and bounded publication adapter ([Gaia portfolio](../github-portfolio-factory.md), [Gaia operator](../github-portfolio-operator.md), [Octopus Sentinel](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/COMMAND-REFERENCE.md#octosentinel), [Hermes webhook guide](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/guides/webhook-github-pr-review.md)).
- **Adoption value:** portfolio-wide evidence, explicit dependencies, bounded worktrees, CI/review reconciliation, and candidate publication fit Gaia's core problem directly.
- **Hidden cost:** GitHub state changes concurrently; branch, PR, issue, workflow, permissions, and billing semantics are repository-specific.
- **Strongest counterargument:** a single-repo tracer with human routing may deliver value sooner than a portfolio scheduler.
- **Simpler alternative:** extend one vertical slice only: survey -> claim one eligible item -> isolated worktree -> independent review -> candidate intent -> human-approved commit/push/PR -> reconcile receipt.
- **Falsifier:** the slice publishes against a different base, repository, branch, diff, review, or issue than the displayed intent.
- **Rejection criterion:** refuse merge, direct issue mutation, repository settings, secrets, billing, or organization administration until each has its own explicit grant/effect adapter and crash matrix.

### 11. Observability — **adopt exact run/attempt/cost spans; preserve content-free telemetry**

- **External capability:** Octopus v10 exposes requested/resolved identities and terminal reasons; OpenClaw exposes structured JSONL plus OTEL; Hermes exposes child trees, token/cost/file rollups, persistent transcripts and optional tracing ([Octopus v10](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/V10-MIGRATION.md), [OpenClaw logging](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/logging.md), [Hermes delegation logs](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/delegation.md#live-transcripts)).
- **Adoption value:** operators need to distinguish liveness, progress, evidence, spend, blockage, and authority. Gaia's control room already does this more honestly than simple “running” indicators ([Gaia control room](../factory-control-room.md)).
- **Hidden cost:** high-cardinality/content-rich traces leak prompts, paths, source, secrets, and reasoning; telemetry failure can accidentally become a control dependency.
- **Strongest counterargument:** immutable transition receipts plus local logs may be sufficient; a tracing stack can become operational theater.
- **Simpler alternative:** add content-free run/attempt/provider/tool/effect span IDs and counters, with exact evidence links retained locally; exporters remain fail-open and loopback-only by default.
- **Falsifier:** dashboard state can claim progress, completion, cost, or freshness not derivable from receipts, or exporter failure changes run semantics.
- **Rejection criterion:** reject raw prompt/output/secret/source telemetry and any monitoring surface that grants, retries, or mutates work.

### 12. Fault recovery — **adopt reconciliation and fencing at every effect adapter**

- **External capability:** Octopus records distinct retry attempts and will not silently rerun a contributed seat; OpenClaw persists fallback state, reconciles tasks, and aborts repeated loops; Hermes reclaims stale Kanban claims and labels crash-ambiguous work `unknown` ([Octopus recovery](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/V10-MIGRATION.md#cancellation-and-recovery), [OpenClaw failover](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/concepts/model-failover.md), [Hermes Kanban](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/kanban.md)).
- **Adoption value:** Gaia's local log already fails closed; extending equivalent rigor across external effects is the highest-value reliability gap.
- **Hidden cost:** every target needs its own idempotency, observation, compensation, and ambiguity semantics; no generic retry policy is safe.
- **Strongest counterargument:** keeping Gaia advisory avoids most effect recovery complexity.
- **Simpler alternative:** one effect-adapter contract requiring intent revision, idempotency key, pre-state digest, attempt generation, external request id, observed result, reconciliation, and `UNKNOWN`.
- **Falsifier:** fault injection produces duplicate irreversible effects, stale lease writes, or a false `completed` state.
- **Rejection criterion:** reject automatic retry for any effect whose prior success cannot be distinguished from failure.

### 13. Security and sandboxing — **integrate real sandboxes; refuse prompt-policy as proof**

- **External capability:** OpenClaw offers Docker/SSH/OpenShell backends and approvals, Hermes offers isolated terminal backends and defense-in-depth command guards, and Octopus offers command/path validation and scheduler policy ([OpenClaw sandboxing](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/gateway/sandboxing.md), [Hermes security](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/security.md), [Octopus security](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/SECURITY.md)).
- **Adoption value:** an actual OS/container boundary can enforce filesystem, process, network, and credential isolation that Gaia's current prompt plus post-hoc Git checks cannot prove.
- **Hidden cost:** Docker socket exposure, bind mounts, remote hosts, browser profiles, and elevated escape paths can negate the sandbox; cross-platform support is expensive.
- **Strongest counterargument:** a dedicated disposable worktree and read-only reviewer may be enough for current tracer bullets.
- **Simpler alternative:** require executor adapters to attest a named isolation profile and observed boundary; start with one Windows-compatible sandboxed read-only review path, not a general sandbox manager.
- **Falsifier:** a negative-control worker can read a denied secret/path, contact a denied network target, write outside scope, or leave a process after cancellation.
- **Rejection criterion:** never describe worktree isolation, file-tool allowlists, or prompt instructions as a sandbox; refuse “trusted operator” defaults for unattended remote work.

### 14. Costs and quotas — **adopt hard budgets and exact attribution where measurable**

- **External capability:** Octopus is strongest here with preflight projections, per-provider usage, hard council caps, scheduler daily/run caps, and kill switches. OpenClaw and Hermes expose estimates, quota windows, and cheaper auxiliary routing, with caveats about missing pricing and cache invalidation ([Octopus costs](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/README.md#what-a-typical-run-costs), [OpenClaw costs](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/reference/api-usage-costs.md), [Hermes cost strategy](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/features/delegation.md#cost-strategy-frontier-planner-inexpensive-workers)).
- **Adoption value:** explicit ceilings on paid cost, tokens, wall time, concurrency, disk, network and human review prevent fanout from becoming the objective.
- **Hidden cost:** subscription quotas, cache reads, tool fees, priority tiers, and provider invoices do not share one trustworthy meter.
- **Strongest counterargument:** a conservative fixed lane cap and user confirmation may be simpler than approximate dollar accounting.
- **Simpler alternative:** require declared upper bounds and record measured tokens/cost plus `UNKNOWN` fields; distinguish a hard provider-enforced cap from an estimate.
- **Falsifier:** a run crosses a declared hard boundary without stopping or the receipt reports a fabricated zero/known cost when the provider did not expose it.
- **Rejection criterion:** reject unbounded recursive fanout and any “cost cap” implemented only as a prompt instruction or delayed dashboard estimate.

### 15. Remote friendliness — **integrate channels and remote hosts; do not add a kernel listener**

- **External capability:** OpenClaw and Hermes run broad messaging gateways and remote nodes/backends; Octopus adjusts its execution defaults for Claude-hosted sessions ([OpenClaw README](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/README.md), [Hermes gateways](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/multi-profile-gateways.md), [Octopus remote sessions](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/README.md#claude-code-web-and-remote-sessions)).
- **Adoption value:** users can inspect, stop, approve, and receive results away from the development host.
- **Hidden cost:** identity linking, sender trust, pairing, replay, delivery ambiguity, multi-user separation, secret storage, and public network hardening become first-class product obligations.
- **Strongest counterargument:** Codex/Claude/OpenClaw/Hermes already solve remote presence. Gaia should provide protocol objects, not another chat product.
- **Simpler alternative:** integrate one remote operator adapter that transports signed intents, approval challenges, stop commands, and redacted receipts; the kernel remains stdio/local.
- **Falsifier:** a sender, replayed message, or stale approval can control a different session, target, or contract revision.
- **Rejection criterion:** refuse shared-gateway hostile multi-tenancy, public unauthenticated ingress, and remote approval that does not display and bind the exact effect intent.

### 16. Human approval — **adopt Gaia's exact-intent pattern everywhere authority crosses**

- **External capability:** peers provide council implementation gates, command approvals, channel approval buttons, and staged memory/skill writes, but they also support no-prompt trusted-operator modes ([Octopus council](https://github.com/nyldn/claude-octopus/blob/6265807f3cdaecca1b0cdb2db92af86ada77ca55/docs/COMMAND-REFERENCE.md#octocouncil), [OpenClaw approvals](https://github.com/openclaw/openclaw/blob/0790d9f593ad30c940ed93b5872a8cf6d6f3cf8c/docs/tools/exec-approvals.md), [Hermes approvals](https://github.com/NousResearch/hermes-agent/blob/5fc308a70719a83cccdbba4c0e39c23f5a8239d5/website/docs/user-guide/security.md)).
- **Adoption value:** Gaia's existing exact display, interactive confirmation, short-lived single-use grant, state remeasurement, and terminal receipt provide a reusable authority pattern ([Gaia operator](../github-portfolio-operator.md)).
- **Hidden cost:** approval fatigue, summary substitution, race windows, and ambiguous remote identity can turn human presence into theater.
- **Strongest counterargument:** low-risk reversible work should not require prompts; approvals can block useful automation without reducing systemic risk.
- **Simpler alternative:** risk-tier authority: read-only/advisory work needs no grant; reversible scoped writes use policy grants; destructive, public, financial, credential, security, merge, and one-way actions require exact just-in-time human approval.
- **Falsifier:** blinded tests show operators accept changed target, state, account, cost, or effect above the declared tolerance.
- **Rejection criterion:** reject generic “approve agent” or “approve plan” tokens; approval must bind operation, target, parameters, state, budget, expiry, subject, and compensation/recovery class.

## Prioritized minimal gap list

This is deliberately a sequence of tracer bullets, not a platform rewrite.

### P0 — prerequisite control-plane gaps

1. **Durable work/attempt/reconciliation contract.** Add immutable work identity, one owner, attempt generations, lease/heartbeat evidence, terminal results including `UNKNOWN`, idempotency key, cancellation, and reconciliation. Prove it with crash injection around one real read-only agent run before adding scheduling or more lanes.
2. **Provider/model/cost resolution receipt.** Record requested and actual provider, model snapshot, effort, auth class, independence class, fallback reason, prompt/schema revisions, measured tokens/cost, and unknown fields. Add hard ceilings for tokens, paid cost, wall time, concurrency and attempts; never label an estimate a hard cap.
3. **Effect-adapter envelope.** Generalize the existing GitHub exact-intent pattern: operation, exact target/state, parameters, capability/authority, idempotency, expiry, budget, remeasurement, result and recovery. Test every boundary from grant through external observation.
4. **Collective-intelligence evidence gate.** Require blind independent first passes, dependency disclosure (provider family, model, context, retrieval corpus, prior answers and judge), a distinct disconfirming method, preserved minority reports, and no majority-derived authority. Start with two subscription-backed lanes and `maxAdditionalPaidCost: 0`, not a larger council.

### P1 — adapters that unlock useful peer capability

5. **Executor adapter manifest.** Describe Claude/Codex/Octopus/OpenClaw/Hermes/wmux runners through immutable manifests: version, tool and data scope, sandbox claim, provider policy, timeout, cost class, output contract, cleanup and receipt. Do not put provider logic in the kernel.
6. **Transport-isolated event adapter.** Put each stdio/SSE/streamable-HTTP/WebSocket adapter in a separately supervised process with bounded input/output, backpressure, connection/session identity, monotonic cursor where the protocol permits, reconnect reconciliation, redaction, and no authority fields. A disconnect produces `UNKNOWN`, never implicit completion or denial.
7. **External-scheduler trigger envelope.** Let Task Scheduler/systemd/Codex/OpenClaw/Hermes wake one pinned Gaia contract with deduplication, expiry and stop semantics. Do not build a cron parser.
8. **MCP/tool capability manifest.** Record exact server/version/transport, tool allowlist, schema digests, credential/data-flow class, timeout and effect class. Let the host own MCP connections; Gaia verifies and receipts selected calls.
9. **Complete one portfolio vertical slice.** Organization survey -> one claimed item -> isolated worktree -> real executor -> independent review -> candidate intent -> exact human-approved commit/push/PR -> reconcile. Keep merge and issue mutation unavailable.
10. **Isolation negative controls.** Add one enforceable sandbox profile for the riskiest current worker path, then prove denied filesystem, network, credential and process behaviors. Continue describing existing worktree/prompt checks as post-hoc guards, not a sandbox.

### P2 — integrate only after a concrete caller proves need

11. **Remote operator transport.** Integrate a channel/gateway for signed intent display, stop, approval and redacted receipt delivery. Keep Gaia without a network listener.
12. **Read-only browser tracer.** Through OpenClaw, Hermes, Codex or another driver, bind profile/origin/tab/snapshot and return evidence only. Add effects later per action class.
13. **Evidence-memory adapter.** Extend Gaia's current hybrid search with validity, invalidation, contradiction and deletion metadata. Do not add personality memory or autonomous memory writes.
14. **Advisory improvement proposals.** Turn repeated failures/corrections into versioned proposals with holdouts and rollback. No self-installation or self-modifying authority.

### Explicit non-goals / refusals

- No feature-count goal such as “all capabilities of all three products.”
- No seventh privileged bus verb.
- No native chat-channel matrix, browser engine, model catalog, skill marketplace, OAuth broker, or sandbox orchestrator unless a measured adapter failure proves the need.
- No unbounded recursive fanout, silent provider fallback, autonomous source/policy/evaluator mutation, or model-written durable memory in the kernel.
- No claim that consensus, a successful process, a heartbeat, an approval click, a worktree, or a sandbox configuration proves correctness.

## Final decision

Gaia should **adopt** durable attempts, provider/cost receipts, effect reconciliation, and exact approval because those deepen its control-plane contract. It should **emulate** progressive disclosure, evidence-grade retrieval, and peer observability without copying their product surfaces. It should **integrate** external executors, MCP servers, schedulers, remote channels, browser/computer drivers, provider routers, sandboxes, and memory engines. It should **explicitly refuse** combined-product parity, a privileged kernel tool surface, unbounded fanout, autonomous self-mutation, silent fallback for authority-bearing work, and ambient trusted-host authority for unattended remote agents.

The minimum success condition is not “Gaia can do everything these systems can do.” It is: **for each useful external outcome, Gaia can name the executing capability, constrain its authority and budget, observe its actual identity and progress, survive or label failure honestly, require exact approval when necessary, and produce a replayable receipt.**
